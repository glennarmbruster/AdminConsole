# Admin Console review — 2026-08-27

Evidence-based, from scanning the 79 scripts as they stand today. Ordered by
what I would actually do first, not by category. Each item says what the
evidence was, so you can disagree with the reading rather than the conclusion.

---

## Do first — these cost you time every day

### 1. Every tool re-parses Common.ps1 on launch — 7,590 lines, 167 functions

Every tool starts with `. (Join-Path $PSScriptRoot 'Common.ps1')`. For an
in-process tool that means the console's process, which has ALREADY parsed
Common.ps1, parses it again into the tool's script scope. For the 12
`OwnProcess` tools it is worse: a new `powershell.exe`, the parse, AND a fresh
EMS/EXO connection.

That re-parse is the single largest fixed cost on every button press, and it
grows with every function added. It is why the console feels slower than it
did in June.

**What to do:** measure it first — `Measure-Command { . .\Common.ps1 }` in a
clean window. If it is under 200 ms, leave it. If it is 500 ms or more, split
Common.ps1 into a core that every tool needs (connections, `Invoke-*Command`,
logging, `Get-LogTarget`) and two or three parts that load on demand: the
report-file controls, the theming, the console-layout helpers. Tools that do
not draw a report do not need `Add-ReportFileControls` parsed.

The `OwnProcess` cost is inherent to the design and correct for the reasons in
ARCHITECTURE 14e. Do not try to fix it by sharing a process; that is the
collision hazard coming back.

### 2. `Test-ToolkitIntegrity` hashes every file at every console launch

`Common.ps1` line ~3979: `Get-FileHashHex` on every code file, every time the
console opens, to produce "103 files verified". That is 100+ SHA computations
before the form appears, and the answer is the same as last time in 99 launches
out of 100.

**What to do:** cache `(relative path, size, LastWriteTime) -> hash` in
`Config\integrity-cache.json` and only rehash files whose size or mtime moved.
Same shape as the capability cache you already have. Startup drops to a
directory listing plus a JSON read.

### 3. `Get-ADGroupMember` is still in two places

The 5,000-member cap that broke Returning User (`NotDeadYet`) on 2026-08-25 is
still present in `Common.ps1` and `DisabledLicensed.ps1`. Same licence group,
same failure waiting to happen — `DisabledLicensed` is a report, so it will
fail on the day someone needs it rather than on a ticket.

**What to do:** the LDAP_MATCHING_RULE_IN_CHAIN query that fixed NotDeadYet,
applied to both. Half an hour.

### 4. Audit log is per-machine (backlog #188)

`Write-CompletedLog` writes locally. Two consequences: the FH story about
attribution only holds if the log survives the workstation, and at Express you
cannot answer "who touched this mailbox" without knowing which machine they
were on.

**What to do:** point `LogPath` at a share, with local fallback when the share
is unreachable and a reconcile on next connect. This is the one backlog item
that a security reviewer would raise unprompted.

## Worth doing — correctness and safety

### 5. Bare colliding cmdlets — CORRECTED, no action needed

The first scan reported ~37 bare calls across 16 scripts. On inspection that
count was wrong: it was matching cmdlet names inside string literals, error
context text, and prose. The genuinely bare calls are in `Rename-OfficeGroups`
and `ManageOwnerGroups`, both `OwnProcess` and therefore isolated by design.
`RoomPlace`, `MailboxHealth` and `MailboxOneDriveAccess` mention the cmdlets
in messages, not calls.

Left in so the correction is on record. A regex scan is not a parse, and the
first number I gave you would have sent you fixing five files that were fine.

### 6. A parameter-name check in Test-Toolkit

`Start-UrlInBrowserProfile -Admin` shipped and failed at run time because
`-Admin` does not exist (`-Purpose 'Admin'` does). Nothing in the verifier
catches a call site naming a parameter that the function does not declare.
The check is: for every call to a `Common.ps1` function, every `-Name` used
must appear in that function's `param()`. I offered this on 2026-08-25; it is
still not built. It would have caught that bug before you did.

### 7. `UnifiedGroupMembership.ps1` has no help block

The only tool without one. Two minutes.

## Features worth tweaking

### 8. A "run this tool against a list" wrapper

Most tools are one-target: one mailbox, one group, one user. The tickets are
not — "these four people", "this list of rooms". Today that means running the
tool four times or writing a one-off. A generic wrapper that takes a CSV and a
tool name, runs it per row in-process, and collects the results into one
report would multiply the value of every single-target tool without touching
any of them.

`Bulk-DLMembership` is the pattern; it just only does one thing.

### 9. Tool windows: cap the zoom rather than leave a margin

Uniform zoom on a tall dialog leaves a wide empty strip on the right at full
screen (Out of Office at 1840 wide uses 1280). Two options: cap the scale so
the window stops growing past what it can use, or let the single output box on
each form absorb the leftover width. The second is better and is a few lines
in `Update-FormScale` — a control tagged as the "stretch" control gets the
remaining width after everything else is scaled.

### 10. Operator display name in the header (backlog #187)

The console shows the connections; it should show who is connected. Matters
more once the log is shared (#4) and someone other than you is reading it.

## Scripts that do not exist and should

Judged against the tickets that came through this week and the ones every
messaging team gets. In rough order of how often they would be pressed.

### 11. Recover deleted items — the #1 helpdesk ticket, and nothing covers it

"User deleted an email / the folder is gone / it was in Deleted Items and now
it isn't." `Get-RecoverableItems` and `Restore-RecoverableItems` in Exchange
Online do this without Compliance Search, per mailbox, with a date window and a
subject filter. No tool touches Recoverable Items except `MBX-Stats`, which
only reports its size.

Read-heavy, one write (the restore), obvious preview-then-apply shape.

### 12. Mobile devices — nothing at all

`Get-MobileDevice` / `Get-MobileDeviceStatistics` / `Remove-MobileDevice` /
`Clear-MobileDevice`. Not one script references any of them. Departing
employees have phones; Disable-User does not list them, let alone remove the
partnership or wipe. This is a gap in the offboarding story, not just a missing
convenience.

### 13. Soft-deleted mailbox recovery

`Disable-User` deletes the AD account and the cloud mailbox soft-deletes.
`Unified-Lookup` can SEE a soft-deleted mailbox. Nothing can bring one back —
`Undo-SoftDeletedMailbox` for the in-window case, `New-MailboxRestoreRequest`
into a fresh mailbox for the "we need the data, not the account" case. The
first time Disable-User is run on the wrong person, this is the tool you will
want and will have to write under pressure.

### 14. Hold and retention — read exists, write does not

Mailbox Health shows litigation hold and retention policy. Nothing sets them.
`Set-Mailbox -LitigationHoldEnabled` and `-RetentionPolicy` are one-line
writes, but they sit in the legal-hold and departing-employee flows where a
preview and an audit row matter.

### 15. Mail contacts

`New-MailContact` / `Set-MailContact` / `Remove-MailContact`. External people
who need to be in the GAL — vendors, auditors, the bank's counsel. Only
`Unified-Lookup` reads them. `ManageMailObject` is the obvious home: a third
radio button.

### 16. Convert mailbox type, standalone

`Disable-User` converts to shared as part of offboarding. The other ask — "this
person left, keep the mailbox as shared for the team, do not disable anything
else" — has no tool, and neither does the reverse ("we hired them back, make it
a user mailbox again", which also needs a licence). `Set-Mailbox -Type` with
the licence check either side.

### 17. Sent-items behaviour on shared mailboxes

`MessageCopyForSentAsEnabled` / `MessageCopyForSendOnBehalfEnabled`. Every
time Send As is granted on a shared mailbox, the next ticket is "my sent mail
is in my own Sent Items, not the shared one." Two booleans. Belongs as a
checkbox in `MailboxPermissions` rather than a tool of its own.

### 18. Reset calendar permissions from a list — promote the one-off

Today's `Set-FSC2027-CalendarPerms.ps1` is the third or fourth time this exact
shape has come up: clear a calendar, grant Editor to this list, Reviewer to
that one. A tool that takes the mailbox and two lists (paste boxes), previews,
and applies would replace the one-off and its successors. `CalendarPermissions`
already has the folder resolution and the grant/remove logic.

## Not recommending

- **Runspaces / background jobs** for the UI freeze. Your own build notes
  reject this and they are right: PS 5.1 parallelism costs more than it saves
  at this scale, and the progress-bar-plus-reentrancy-guard pattern from
  `MailboxPermDupe` is the correct answer for the rest of the toolkit too.
- **A Graph tool** (backlog #191) until there is a specific need. Every EXO
  cmdlet you use today has no Graph equivalent worth the consent conversation.
- **Merging the tenant-neutral build back in.** Deleting it was right.

## If you do three things

1. Cache the integrity hashes (#2). Fastest visible win, lowest risk.
2. Fix `Get-ADGroupMember` in the two remaining places (#3). Known bug, known fix.
3. Build Recover Deleted Items (#11). Most-pressed button you do not have.
